OpenGPU DWT_INV for Progressive (2026-11-05)
============================================

Goal: move RemoteFX Progressive inverse DWT off the 68040 onto OpenGPU
(CPU back end first; ACRTG host GPU later).

OpenGPU (DalsinAI/gfopenrtg)
- stream v1.9: OGPU_OP_DWT_INV (0x0029)
- Words: in addr, out addr (0=inplace), flags, work addr, work bytes
- Flag OGPU_DWT_RFX_RE = Reduce-Extrapolate
- Work: OGPU_DWT_RFX_WORK_BYTES (same layout as GFAmigaRDP RDP_PROG_TMP)
- CPU implementation: library/opengpu/ogpu_dwt.c (ogpu_rfx_idwt)
- Query: OGPU_Query(OGPU_OP_DWT_INV, OGPU_FMT_ARGB32) → OGPU_FULL on CPU core
- Host test: tests/test_dwt.c (forward+inverse roundtrip, max err ≤ 8)
- Bit-exact with [MS-RDPRFX] 3.1.8.2.4 lifting and rdp_prog_idwt

GFAmigaRDP
- Hook rdp_progressive_set_idwt; Amiga ogpu_dwt.c Query+Submit
- CPU rdp_prog_idwt remains the fallback when Query is NONE / Submit fails
- Install alongside YUV pilot from session_win

Still needs GPU backend
- ACRTG.gpu / PiStorm.gpu do not accelerate DWT_INV yet (Query without
  OGPU_ONGPU_BIT; library falls through to CPU core). A host shader / compute
  path would set OGPU_ONGPU_BIT in supports().

Clean-room: MS-RDPRFX + existing AmigaChrome OpenGPU patterns; no FreeRDP.
