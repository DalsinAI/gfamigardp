GFAmigaRDP 0.1 - on an AmiCradle lab machine
=============================================

What is here (copy the whole drawer, e.g. to Work:GFAmigaRDP/):

  GFAmigaRDP           the client (68040, soft float: no FPU needed)
  tools/RDPProbe       TCP + X.224 + TLS + NLA from the Shell, against a real computer
  tests/X224Test       the X.224 encoder/decoder checks (prints "x224: ok")
  tests/GFOpenNTLMVectors    gfopenntlm's checks (MS-NLMP 4.2 and RFC vectors), linked in
  tests/GFOpenNTLMLibTest    the same API through LIBS:gfopenntlm.library
  tests/GFOpenNTLMStaticTest the API linked in
  Libs/gfopenntlm.library    NTLMv2 and CredSSP for NLA: copy to LIBS:
  Libs/gfopentls.library, Libs/gfopencrypto.library   TLS: copy to LIBS:
  Themes/*.theme       GFOpenGadTools themes: Open, Classic, Graphite, Glass, Clear, Sky, Ember
  Env/GFOpenGadTools/Look   "Open": the theme to use
  lib/libolui.a        the GFOpenLayout UI library, for reference only: it is
                       linked into GFAmigaRDP and is not needed at run time
  SHA256SUMS

Needs
  AmigaOS 3.2 (3.2.3 tested target), a 68040 or 68060.
  ROM/LIBS: exec, dos, graphics, intuition, layers, gadtools.library,
  keymap.library, diskfont.library (all part of 3.2); locale.library optional.
  timer.device.
  Fonts: the screen font (topaz.font 8 at least). Any font the theme names is
  opened through diskfont.library; when it is missing the screen font is used.
  NOT needed: gfopenlayout.library (the UI is linked in statically, library
  version 11's strip and key calls included), opengadtools.library.
  Optional: cybergraphics.library v40 (or P96's) for the true-colour desktop
  through WritePixelArray; without it the desktop is dithered to pens with
  WriteChunkyPixels.
  For a real connection only: bsdsocket.library v4 (Roadshow or another
  stack), gfopentls.library and gfopencrypto.library in LIBS:, and for NLA
  gfopenntlm.library 1 too (it opens gfopentls.library for random bytes).

Install the theme (once)
  Copy Themes/#?.theme SYS:Prefs/Presets/Themes/
  Copy Env/GFOpenGadTools ENVARC:GFOpenGadTools ALL
  Copy Env/GFOpenGadTools ENV:GFOpenGadTools ALL
  To try another look: SetEnv GFOpenGadTools/Look Classic  (then start again)

Screenshots - no server needed
  GFAmigaRDP DEMO
      the connection window with sample favourites; Connect (the button,
      Amiga-O, or C when no text field is active) opens the demo session;
      Cancel or Esc quits. Underlined letters jump to their field or button.
  GFAmigaRDP DEMO SESSION
      straight to the session window: toolbar, test pattern desktop
      (gradient, grid, grey ramp, colour bars), status bar.
      Amiga-D goes back to the connection window, Amiga-Q quits.
  GFAmigaRDP DEMO SESSION HOST=lab-pc USER=alice
      the same, with that name in the toolbar.
  Run them on a 16- or 24-bit RTG Workbench for the true-colour pattern, and
  on an 8-colour AGA/ECS Workbench to see the dithered fallback.

Real connection (connection initiation only in 0.1)
  GFAmigaRDP                         the window; Connect probes the computer
  tools/RDPProbe HOST=192.168.1.10   prints what the computer chose
  tools/RDPProbe 192.168.1.10 USER=alice DOMAIN=LAB PASSWORD=...
      also logs on with NLA (CredSSP over NTLMv2) and prints the result: the
      server's errorCode as an NTSTATUS name when it refuses. The password
      is never printed (but it is in the Shell's history: type it in a
      Shell you close afterwards). ASKPASS asks for it with nothing shown.
  tools/RDPProbe 192.168.1.10 USER=alice ASKPASS ACTIVATE WAIT=5
      on past licensing: Demand Active, Confirm Active, the finalization,
      then WAIT seconds of what the computer sends, and the last PDUs in hex.
  What the client data offers can be changed to see what a server asks of
  it: CHANNELS=drdynvc,cliprdr (TS_UD_CS_NET), EARLY=hex (earlyCapability-
  Flags, default 0001), DEPTHS=hex (supportedColorDepths, default 0007),
  BPP=8|15|16|24. These are for finding out, not for use: GFAmigaRDP itself
  offers only what it has.
  GNOME Remote Desktop (tested 2026-11-05, NLA with HYBRID_EX) sends Deactivate
  All and Disconnect Provider Ultimatum reason 3 (rn-user-requested) straight
  after licensing unless the client offers the Graphics Pipeline, a 32 bpp
  session and drdynvc together:
      default (no channels, 0001, 0007, 16 bpp)   dropped
      CHANNELS=drdynvc                            dropped
      CHANNELS=drdynvc EARLY=0101                 dropped
      EARLY=0003 DEPTHS=000F BPP=24               dropped
      CHANNELS=drdynvc EARLY=0003 DEPTHS=000F BPP=24   dropped
      EARLY=0103 DEPTHS=000F BPP=24               dropped
      CHANNELS=drdynvc EARLY=0103 DEPTHS=000F BPP=24   Demand Active (14 sets,
          1024 x 768 at 32 bpp), finalization done (Font Map), then the DYNVC
          Capabilities Request on drdynvc, waiting for the RDPGFX channel.
  So that server needs [MS-RDPEDYC] and [MS-RDPEGFX] in the client.
